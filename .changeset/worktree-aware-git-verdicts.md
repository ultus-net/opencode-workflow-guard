"opencode-workflow-guard": patch
---

Judge git commands against the tree they actually run in, and stop denying cwd-dependent commands from the wrong checkout.

- `parseGitInvocation` accepts the shell's `workdir` as its base directory, so branch, mergeability, and protected-branch checks judge the checkout the command runs in rather than the session-bound one.
- A linked worktree of the same repository is no longer treated as foreign state for git mutations and pushes.
- PR preflight resolves `gh --head` / `-H` and `az --source-branch` to the worktree holding that branch, and the merge check takes the resolved ref instead of `HEAD`. A named source branch that no local checkout holds is refused, because review and merge evidence bind to the content of a checkout: substituting the caller's tree would let an approval of one tree satisfy a PR that publishes another.
- The V2 permission seat defers cwd-dependent commands (`git push`, history writes, branch creation, PR creation) with code `repository_unidentified` instead of judging the session-bound checkout. An explicit `-C`/`--git-dir`/`--work-tree`/`GIT_DIR` stays decisive, and so does a push to `main` or `master`; a configured `protectedBranches` destination defers like any other cwd-dependent verdict. A block from another policy in the same compound command keeps its denial.
- A repository claim is only an assignment: `GIT_DIR=` inside a commit message is message text, not a repository selector, including through `env`/`sudo`/`timeout` wrappers. A repository selection that cannot be resolved (`git -C $OTHER_REPO`) stays a boundary block even when the session's own workspace is a repository, because the linked-worktree exemption would otherwise resolve it to the workspace's own root.
- A shell `workdir` in a different repository is not judged. The command runs there, so a relative target (`rm -rf dist`, `> artifact.txt`) would be validated against the workspace root while changing another tree. Recognized mutations and git writes in that workdir are blocked as a workspace escape, and reads there stay allowed. Recognized shell mutations are validated against the linked worktree the command actually runs in, so a `workdir` in a linked worktree of the same repository is judged where it lands.
- An in-command `cd`, `pushd`, and `popd` now moves the directory later segments are judged in. `planShellSegments` walks the command and resolves each segment's own root, so `cd <other-repo> && git commit` is a write in that other repository instead of a commit in the session's checkout. The same walk drives shell-mutation validation, redirect snapshots, and the protected-branch check, so `cd nested && echo x > artifact.txt` is judged where the file actually lands. A `cd` inside a grouping subshell is scoped to it, so `( cd /other && ls ) && rm -rf dist` still removes inside the workspace.
- A wrapper that changes directory (`env -C`, `sudo -D`, `--chdir`) is followed too. Its target moves only its own command, so `env -C <other-repo> git commit` is judged against that repository.
- The walk expands only the forms a shell expands deterministically (`~`, `~/…`, `$HOME`, `${HOME}`) and leaves everything else alone. An indeterminate target (`cd $DIR`, `cd -`, a `pushd` onto an untracked stack) is reported as indeterminate and fails closed for a mutation. Reads stay allowed.
- A nested interpreter payload is judged against its own declared tree. `bash -c 'cd <other-repo> && git commit'` is one shell word to the outer shell, so its nested `cd` was invisible. The guard now re-plans each payload and reads a working directory only where one actually applies: a spawn-family `cwd` (`execSync`, `spawn`, `fork`, …) or `process.chdir`. A bare `{cwd: …}` key in an unrelated object does not name a working directory, so it cannot foreign-flag a payload that writes in the workspace. A payload that mutates outside the workspace, and is not a linked worktree of it, is refused, and a payload whose working directory is not a literal (`{cwd: process.env.OTHER}`) fails closed for a mutation the same way the shell rule does.
- A trailing `-C`/`--git-dir` with no value names no repository but still carries the flag, so `parseGitInvocation` reports it as an explicit claim. The permission seat and `execute.before` then agree the command is unclassifiable instead of one judging it and the other deferring it.
- Host session moves rebind the session workspace, journaled as `workspace.binding` / `workspace_rebind_session_move`. Only a genuine move rebinds: an announced `session.moved`, or an update naming a new directory. The event name now matches the pinned 2.2.0 SDK, where `session.next.moved` does not exist and `session.moved` carries `data.sessionID` plus the destination `data.location.directory`. A routine title or cost update no longer drags a session out of the linked worktree its own tool calls bound it to.
- A verification timeout now tells the agent the truth about the remedy. The limit is set by the user, in the project `.opencode/workflow-guard.json` or `.jsonc`, or by `WORKFLOW_GUARD_VERIFY_TIMEOUT_MS` before the guard starts. The public type surface exports `VerifyRun`.
