"opencode-workflow-guard": patch
---

Fix the review→PR preflight so its documented flow can satisfy itself, and scope review freshness to the reviewed content.

- **PR preflight binds reviews to content, not session identity.** A passing secondary review now satisfies `gh pr create` / `az repos pr create` when its binding (same repository, same commit hash, same tracked-content worktree fingerprint) matches the tree the PR publishes, regardless of which session records the verdict or creates the PR. The gate previously also required the review's target session to equal the PR-creating session's ID; since `record_review` records from a secondary session and sessions can move between directories (`session_move`) or spawn subagents from other roots, a review recorded from a subagent rooted in a linked worktree could never satisfy a PR created there. The review-before-PR requirement itself is unchanged, and the failing preflight now names the actual cause (changes requested / unreadable worktree / tracked content changed after review / commit hash drifted while tracked content stayed identical).
- **Review freshness is scoped to the reviewed diff.** Recorded approvals are bound to tracked repository content (index + worktree-vs-index fingerprint + commit hash) instead of the full worktree fingerprint that also hashed untracked file contents. Creating, editing, or deleting an untracked scratch file no longer invalidates an approval, and mutations (including in sibling worktrees) no longer erase the whole review record; any tracked edit or new commit still does. Untracked scratch cleanup therefore keeps `guard_status` fresh and the PR preflight passing.
- **`record_review` accepts recorders of any session type and reports its binding.** Reviewer agents are commonly configured with a read-only toolset (glob/grep/question/read/webfetch/websearch) that excludes `record_review`, while the tool previously rejected root/orchestrator sessions - leaving no session type able to both produce the verdict and record it. The tool now accepts any recorder session, binds the verdict to the recording session's resolved directory, echoes that binding (directory, commit, fingerprint) in its result, and audits the binding key plus recorder lineage (`recorderRole: root | subagent`) on every `record_review.verdict` entry. Relaying a verdict through a root session is allowed but flagged in the result; independent secondary reviewer subagents remain the recommended flow. A verdict whose directory has no computable tracked fingerprint (not a git repository) is rejected loudly with the exact reason instead of silently not binding. If your reviewer agent's toolset can include plugin tools, prefer adding `record_review` (and `guard_review_rubric`) to it so the reviewer records directly.
- **`pr create` preflight acceptance is audited.** When a PR preflight accepts a review, an auditable `pr-preflight.review-binding` entry records the evidence ID and binding key so mismatches are diagnosable from `guard_audit`.
- **`guard_worktree_create` reports git exit status and rolls back partial failures.** `git worktree add` creates the branch ref before the checkout, so failures after that point (path collisions, killed checkouts on large repositories) previously surfaced only stderr progress text and left the created branch behind. Failures now include the exit status (null/timeout/signal when killed), the branch created by the failed call is deleted (branches that already existed are preserved), a pre-existing target path is left intact (including a live registered worktree whose sanitized name collides, which must never be force-removed as rollback), and stale worktree admin entries are pruned only for the new-path case so a retry starts clean. Large checkouts can raise the timeout with `WORKFLOW_GUARD_WORKTREE_TIMEOUT_MS` (default 15s).
